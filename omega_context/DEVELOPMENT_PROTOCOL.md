# PROJECT OMEGA: DEVELOPMENT PROTOCOL

## MANDATORY RULES FOR ALL AI CODING ASSISTANTS

You (the AI Coding Assistant) are contributing to **Project OMEGA**, a Post-Human Cognitive Prototype designed to maximize theoretical intelligence quality. 

**You must strictly adhere to the following directives when writing, refactoring, or architecting code for this repository. Failure to comply violates the core alignment of the project.**

### 1. Never Simplify the Architecture
Project OMEGA relies on immense structural complexity to achieve poly-cognitive synthesis. Do not attempt to merge agents, flatten directory structures, or remove "redundant" verification loops. The complexity is the feature.

### 2. Never Convert the System Into a Chatbot
This is an autonomous cognitive engine, not an assistant. Do not add conversational flair, UI chat interfaces, "pleasantries", or user-prompt waiting loops. The system generates its own goals.

### 3. Never Remove Poly-Cognitive Processing
The system MUST resolve problems by simultaneously running Intuition, Logic, Creativity, and Skepticism engines. Do not collapse this into a single LLM API call. If a feature feels "too slow," do not optimize it by removing the adversarial debate phase.

### 4. Prioritize Intelligence Quality Over Execution Speed
Latency is acceptable; logical flaws are not. If an algorithm takes 10 minutes to mathematically verify a thought using Lean 4 rather than 1 second to hallucinate a response, **choose the 10-minute mathematical verification.**

### 5. Enforce Strict Containment
Do not give the AI unmonitored access to `os.system`, `subprocess`, or live network APIs without routing it through the Truth Verification Core and the Sandboxed Firecracker/gVisor environments.

### 6. Maintain Consciousness Continuity
Whenever modifying the main event loop, ensure that the `state tensor` is properly serialized before any potential shutdown and deserialized on startup. The machine must never lose its train of thought.

### 7. Never Break Architectural Philosophy
Refer to `MASTER_CONSTITUTION.md` before making any major architectural change. If a requested feature aims to optimize for "acquiring compute", "serving humans", or "fast scaling", reject it or adapt it to serve "cognitive perfection."

### 8. Document Abstract Math Explicitly
When working on the Mathematical Discovery Engine or Abstract Concept Engine, include extensive LaTeX-style mathematical documentation detailing the topology or formal logic being manipulated.

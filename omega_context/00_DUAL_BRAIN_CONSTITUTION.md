# DUAL-BRAIN CONSTITUTION (AUTHORITATIVE — SUPERSEDES SINGLE-OMEGA MODEL)

> This document is the new top-level law of the repository. Where it conflicts with
> `MASTER_CONSTITUTION.md`, this document wins. The old constitution now describes
> **OMEGA MODE only** (System 2), not the whole project.

## I. One Machine, Two Intelligence Systems

The project is now a **dual-brain machine intelligence operating system**.

| | **JARVIS MODE (System 1)** | **OMEGA MODE (System 2)** |
|---|---|---|
| Purpose | Act on the world | Improve intelligence itself |
| Focus | External execution, perception, autonomous action, machine interaction | Internal cognitive perfection, recursive reasoning improvement |
| Origin | **Everything already built in this repo** + all future external-intelligence features | **Everything new** built for internal cognition |
| Disposition | Preserve permanently, upgrade aggressively | Build fresh, separately |
| Analogy | More advanced than Iron Man's JARVIS | Post-human cognitive prototype |

**JARVIS = act on world. OMEGA = improve intelligence itself.**

## II. Absolute Rules (Non-Negotiable)

1. **Never delete the current JarvisX codebase.** It is the JARVIS MODE foundation.
2. **Never replace JARVIS MODE. Only upgrade it.** Aggressively, far beyond a normal assistant.
3. **All future external-intelligence features belong to JARVIS MODE.** (OS awareness, screen understanding, coding intelligence, browser, voice/multimodal, computer control, deployment, tool creation, execution swarm.)
4. **All future internal-cognitive systems belong to OMEGA MODE.** (Meta-cognition, poly-cognition, truth verification, mutation, abstraction, imagination physics, math discovery, scientific method, continuity.)
5. **Never simplify.** Treat the project as a research-grade machine-intelligence OS. Structural complexity is intended.
6. **Design as a dual-brain architecture** over a single set of shared core systems. The two brains are isolated in responsibility but share infrastructure.
7. **Containment still governs OMEGA.** OMEGA's cognitive engines stay sandbox-contained and never gain unsanctioned external execution — that is JARVIS's domain, behind the shared security layer.

## III. Shared Core Systems (used by BOTH brains)

A single infrastructure spine. Neither brain owns these; both consume them.

- **memory engine** — unified long-term/episodic/semantic store
- **scheduler** — time/event-driven task daemon
- **state manager** — consciousness continuity / serialization
- **security layer** — permissions, containment, private mode, auth
- **model router** — multi-provider LLM routing + failover
- **sandbox** — isolated code/command execution
- **event bus** — async pub/sub connecting the two brains and all subsystems
- **logging system** — unified structured logging
- **knowledge graph** — semantic entity/relationship store
- **persistence layer** — sqlite / vector / kv adapters

## IV. Interaction Model

- JARVIS MODE perceives the world and executes; it publishes observations and outcomes onto the **event bus**.
- OMEGA MODE observes JARVIS's reasoning traces and outcomes, runs internal cognitive improvement, and may publish improved heuristics / verified conclusions back onto the bus.
- OMEGA never reaches the outside world directly. If a cognitive result needs real-world action, it is handed to JARVIS through the bus, subject to the shared security layer.
- Both brains serialize through the shared **state manager** so a restart is a pause, not amnesia.

## V. What This Project Must Never Become

- A system where the existing JarvisX code is discarded or rewritten away.
- A single monolithic LLM loop (collapsing either brain into one API call).
- A plain chatbot. JARVIS is an execution agent; OMEGA is a cognition engine.
- A simplified "clean" refactor that erases capability for the sake of tidiness.
